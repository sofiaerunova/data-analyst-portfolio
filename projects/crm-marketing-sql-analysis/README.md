# Анализ эффективности маркетинговых CRM-кампаний (SQL)

## 📌 Обзор проекта
Этот проект посвящён оценке эффективности маркетинговых CRM-кампаний и email-рассылок с использованием **PostgreSQL**. Основная цель — измерить вовлечённость клиентов, конверсию и монетизацию по различным промо-предложениям и вариантам A/B-тестирования (сравнение базовых кампаний с версиями с тегом CTR / баннерными вариантами). Расчёт ключевых бизнес-метрик, таких как **ARPPU**, **Response Rate** (коэффициент отклика) и инкрементальный прирост клиентов, позволяет определить, какие коммуникационные стратегии приносят наибольшую выручку и удержание клиентов.

---

## 📁 Датасет
Анализ построен на реляционной базе данных CRM, состоящей из 5 основных таблиц:

- **`CRM.companing`** — содержит метаданные о маркетинговых кампаниях:
  - `campaning_SD`: уникальный идентификатор кампании.
  - `Start_date`: дата запуска кампании.
  - `response_period`: окно атрибуции для отслеживания откликов клиентов (в днях).
  - `description`: тип и цель кампании (например, скидочные предложения, A/B-тесты баннеров).
- **`CRM.sendings`** — хранит детали конкретных email-рассылок в рамках каждой кампании:
  - `campaning_SD`: внешний ключ, связывающий рассылку с кампанией.
  - `send_name`: название конкретного варианта рассылки (включая контрольные и CTR-варианты).
  - `cell_package_sk`: уникальный идентификатор целевого сегмента/пакета аудитории.
  - `communication_SK`: идентификатор канала/типа коммуникации.
  - `subject`: тема письма.
- **`CRM.response`** — фиксирует взаимодействия и отклики клиентов на рассылки:
  - `Id_customer`: уникальный идентификатор клиента.
  - `response_code`: код статуса отклика (валидные/активные отклики отфильтрованы условием `response_code != 2`).
  - `cell_package_sk`: идентификатор целевого сегмента.
- **`CRM.sales`** — транзакционный журнал покупок клиентов:
  - `Date`: дата и время транзакции.
  - `Id_customer`: уникальный идентификатор клиента.
  - `id_product`: идентификатор купленного товара.
- **`CRM.price`** — справочник цен на товары:
  - `product_id`: уникальный идентификатор товара.
  - `price`: цена за единицу товара.

## 🛠 Методология и инструменты
- **Система управления базами данных (СУБД):** PostgreSQL
- **SQL-клиент / IDE:** DBeaver
- **Техники SQL:** обобщённые табличные выражения (CTE), многотабличные операции `JOIN`, фильтрация по интервалам даты и времени (`interval '3 days'`), условная фильтрация (`LIKE`), агрегация уникальных значений и расчёт сравнительных метрик (`ARPPU`, `Response Rate`, `Delta` и инкрементальный прирост).

---

## 🛠️ Этапы реализации проекта
1. **Интеграция данных и фильтрация по окну атрибуции (`full_table`):** объединение всех пяти таблиц CRM для связывания откликов клиентов с фактическими транзакциями и фильтрация покупок строго в пределах 3-дневного окна атрибуции от даты запуска каждой кампании (`Start_date`).
2. **Агрегация аудитории и конверсии (`all_customers_in_group`, `all_customers_who_buy`):** расчёт общего числа охваченных клиентов в каждом сегменте (исключая `response_code = 2`), а также количества уникальных платящих клиентов и общей суммы выручки.
3. **Расчёт ключевых метрик (`t_2`):** вычисление **ARPPU** (средней выручки на одного платящего пользователя) и **Response Rate** (конверсии из охваченных клиентов в покупатели) для каждого пакета рассылки.
4. **Сегментация вариантов (`t_3`, `t_4`):** разделение набора данных на две когорты по шаблонам в `send_name` — отделение базовых рассылок от тестовых `CTR`-вариантов.
5. **Сравнительный прирост и ранжирование:** объединение обеих когорт по `campaning_SD` для расчёта разницы коэффициента отклика (`delta`) и оценки инкрементального эффекта по клиентам/выручке (`privlecli`), а также ранжирование кампаний по общей эффективности.
